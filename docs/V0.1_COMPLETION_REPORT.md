# Local Agent Scheduler V0.1 Completion Report

Status: implementation complete; live model-consuming Codex smoke not run

Package: `local-agent-scheduler 0.1.0`

## Implemented scope

V0.1 implements a single-process, local-first Scheduler backed by SQLite WAL.
It owns durable Batch, Task, Attempt, Lease, Execution, Result, Failure,
Escalation, LogicalAgent, Incarnation, PoolPartition, Workstream, Checkpoint,
topology revision, and notification outbox state.

Execution is explicitly at-least-once. Authoritative mutations require a
current Attempt, ACTIVE unexpired Lease, matching fencing epoch, and matching
`task.current_attempt_id`. No exactly-once claim is made.

The process contains a pool reconciler, dispatcher, startup recovery path,
Result Queue, notification outbox, Codex app-server ExecutionAdapter, Codex
app-server RootBridge, provider-free filesystem RootBridge, strict TOML config,
and diagnostic/control CLI.

## State machines and transaction boundaries

The frozen transition matrices are in [V0.1_SPEC.md](V0.1_SPEC.md). The critical
single-transaction boundaries are:

1. Batch, Task graph, dependencies, and initial eligibility.
2. Claim, fencing increment, Attempt, Lease, and LogicalAgent assignment.
3. Success ACK, Attempt/Lease close, Task completion, Result AVAILABLE,
   dependency release, Batch recomputation, and notification outbox insertion.
4. Failure recording plus deterministic retry, or suspension plus Escalation
   and decision-required notification.
5. Fenced checkpoint promotion and bounded continuity replacement.
6. Topology revisions with MOVE, MERGE, retirement, drain, and capacity change.

`Task COMPLETED + Result AVAILABLE` is atomic. Root notification and Result ACK
are later independent operations and cannot roll back Task or Batch state.

## Schema summary

Schema version 1 is recorded in `schema_migrations`. SQLite runs with foreign
keys, WAL, `synchronous=FULL`, and `BEGIN IMMEDIATE` writes. Partial unique
indexes prevent multiple ACTIVE Attempts/Leases for one Task and multiple open
Escalations. Results are unique per Task.

Runtime state exists only in SQLite. TOML contains human-authored policy and
external integration references. No scheduler state database, registry, or
provider routing layer exists outside SQLite.

## Recovery and writer safety

Daemon startup moves through `RECOVERY` before `READY`. Overdue Leases are
fenced before execution observation, so a late heartbeat cannot revive expired
authority. Still-authoritative Codex executions are reconciled by persisted
thread and exact turn identity. Stale terminal outcomes update Execution
history only.

Read-only work follows its declared retry policy. A shared-workspace writer is
not replaced merely because its Lease expired. Replacement requires confirmed
quiescence or an ExecutionTarget that declares attempt isolation; otherwise the
Task and Batch suspend and a `WRITER_QUIESCENCE_UNKNOWN` Escalation is created.
The LogicalAgent also remains unavailable for unrelated work. Cancellation
revokes authority but applies the same physical-quiescence guard; the explicit
`release_cancelled_writer` recovery operation is required before revival.
Current workspace state is authoritative for a subsequently approved retry.

Physical Incarnation loss does not retire LogicalAgent identity. Revival creates
a replacement Incarnation and restores committed continuity. RETIRED is
semantic death and cannot revive. Required affinity with no compatible live
identity causes a newborn LogicalAgent synchronized from Workstream project
state.

## Execution and Root boundaries

Scheduler Core imports no Codex, DeepSeek, CCR, TokenRhythm, provider, or model
mechanics. `ExecutionAdapter` exposes start, observe, interrupt, terminate,
outcome collection, and start reconciliation. `RootBridge` is separately
injected and cannot mutate scheduling state.

The Codex adapter uses official app-server JSONL methods: `thread/start`,
`turn/start`, `thread/read`, and `turn/interrupt`. The Codex RootBridge uses
`thread/resume` and a notification `turn/start`, waiting for the matching
`turn/completed`. Notification text contains event identity and entity indexes,
not Result payload.

Adding an OpenCode adapter requires a new adapter implementation and
configuration/CLI selection; it does not require changing Core state machines.

## Test evidence

Run:

```powershell
python -m unittest discover -s tests -t . -v
python -m compileall -q src tests
```

The provider-free suite covers:

* atomic normal Result flow and Root-unavailable delivery;
* dependencies and transactional claims;
* retry, exhaustion, suspension, and partial Batch preservation;
* expired/stale Lease ACK, heartbeat, execution, and checkpoint fencing;
* writer unknown-quiescence suspension and cancellation fencing;
* Batch/Task cancellation and retained completed Results;
* resident/ephemeral agents, birth, revival, semantic retirement, MOVE/MERGE,
  partition drain, and workstream-affinity birth;
* ambiguous start and persisted Codex turn recovery;
* filesystem and Codex RootBridge behavior without a provider request;
* strict configuration and lifecycle state;
* a two-process SQLite restart integration: process one claims then exits;
  process two reopens, reconciles, and verifies database integrity.

An independent architecture-integrity audit was performed after implementation.
It found and prompted fixes for unexpired-authority validation and persisted
Codex turn recovery. The complete suite passed after those fixes.

## How to diagnose

Use `status`, then inspect the authoritative entities:

```powershell
local-agent-scheduler --config config/scheduler.example.toml status
local-agent-scheduler --config config/scheduler.example.toml task list
local-agent-scheduler --config config/scheduler.example.toml execution list
local-agent-scheduler --config config/scheduler.example.toml result list
local-agent-scheduler --config config/scheduler.example.toml escalation list
local-agent-scheduler --config config/scheduler.example.toml outbox list
local-agent-scheduler --config config/scheduler.example.toml pool show
```

Use `recover` after an unclean stop. Resolve an Escalation only after inspecting
its snapshot. A writer retry requires `--confirm-quiescent`; otherwise it remains
suspended. Use execution interrupt/terminate when a runtime still has an
attachable physical handle. Never repair authority by editing SQLite manually.

## Known limitations and deferred features

* V0.1 is single-machine and single-daemon; there is no HA or leader election.
* Codex creates a dedicated physical thread per Execution. Warm thread reuse is
  optional and not implemented; correctness does not depend on it.
* Shared-workspace writer isolation is not implemented. Unknown quiescence
  therefore suspends instead of launching a replacement.
* Continuity is a bounded structured capsule, not a transcript or vector-memory
  service.
* Pool SPLIT, workflow DSL, automatic decomposition, semantic recovery planning,
  dashboards, provider routing, and credential pools are deferred.
* The current configuration loader wires the first adapter type, Codex
  app-server. Adding another target type changes adapter/configuration wiring,
  not Core.
* The local installed app-server protocol schema and all adapter paths were
  checked provider-free. No live model-consuming Codex execution or Root wakeup
  was triggered during completion, so deployment-specific credentials,
  approvals, sandbox behavior, and provider capacity remain a live-smoke item.

## Architecture deviations

No Core Invariant was intentionally changed. The implementation does not copy
the architecture overview into a generic framework: it uses one SQLite process,
one narrow adapter protocol, one narrow RootBridge protocol, and no scheduler
LLM, RPC framework, external queue, or second runtime.

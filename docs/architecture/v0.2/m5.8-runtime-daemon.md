## Frozen phrases

Recovery grants this Runtime the right to begin activation; it does not by itself grant production dispatch capability.

Physical observation does not renew authority. It determines whether existing supervision remains eligible to renew.

A stale physical observation stops future renewal eligibility; it does not manufacture death, termination, or quiescence.

Process singleton ownership is an OS Runtime property, not a Scheduler Lease.

Daemon shutdown stops Scheduler mechanics. It does not cancel semantic work or terminate external agents.

The only safe recovery from a failed Runtime component is a new Runtime lifecycle through the full restart barrier.

The production composition root exposes host control and diagnostics, never Worker acknowledgement.

Worker acknowledgement is a data-plane capability. It is not a host capability and is not reachable from the daemon.

## Composition

One Scheduler store has exactly one production `SchedulerDaemon`.

```text
SchedulerDaemonBuilder.start()
        ↓
RuntimeProcessLock (file identity, not the parent directory)
        ↓
Kernel::open
        ↓
recover_runtime  → RecoveredRuntime (activation right only)
        ↓
physical-observation activation sweep
        ↓
ReadyPermit
        ↓
ControlLoopRunner + PhysicalObserverRunner
        ↓
READY
```

The identity lock follows the open file handle, not a second lookup of
the path. Unix flocks that inode. Windows locks a file under the machine
ProgramData known folder, named only from the handle's volume and file
index — not the `Local\` namespace, and not the database's current
directory. A byte-range lock on the database would collide with SQLite.
A canonical-path sidecar still excludes two processes that open the same
path. Renaming the store into another directory does not mint a second
daemon.

A new physical start takes its dispatch permit before any claim. If
shutdown or a fatal already won the gate, no Attempt is created and no
retry budget is spent. `abort_before_physical_start` remains only for a
STARTING row that never reached the adapter.

Recovery proves this runtime owns each current RUNNING execution.
Fresh renewal eligibility is required only by the check after the
activation sweep, which is what mints `ReadyPermit`.

`ControlLoopService` cannot be constructed without `ReadyPermit`.
`Dispatcher::dispatch_one` remains a test-support path.

## Host control surface

The daemon lends exactly one control surface, `SchedulerControl`, and it is
narrower than `Kernel` by construction. A host may submit a Batch, cancel a
Task or Batch, manage pool topology, acknowledge a consumed Result,
acknowledge a delivered Root notification, and read durable state.

Three families are deliberately unreachable:

```text
Worker acknowledgement      ack_success / nack / nack_preserving_physical_history
Runtime-owned mechanics     claim, execution commit, physical outcome, lease
                            expiry, retry promotion, recovery, revival,
                            renewal, outbox delivery pipeline
Writer-quiescence override  cancel_task's quiescence_confirmed argument
```

`SchedulerControl` borrows its daemon, so it cannot outlive the process lock.
It has no public constructor, so it cannot be forged from a borrowed Kernel.
`Kernel` itself is not part of the production daemon API.

The control surface never asserts writer quiescence: the override argument is
absent, so a host cannot claim a proof it does not hold. Cancelling a writer
whose quiescence is unproven still suspends the logical agent and opens a
`WRITER_QUIESCENCE_UNKNOWN` Escalation, exactly as the Kernel primitive does.

`resolve_escalation` is deliberately outside this surface. Escalation
resolution selects a recovery primitive, so it stays with the Escalation
milestone rather than arriving as a side effect of composition closure.

Production Lease renewal is `renew_supervised_execution_guarded` only: it is
fenced by the positively admitted execution identity and re-checked against
physical freshness inside the write transaction. `renew_supervised_execution`
(no freshness guard) and `Kernel::heartbeat` are legacy primitives, test
surface only, and are not the daemon loop.

A positive physical observation re-establishes freshness. That is a
scheduling action with two halves: it re-arms the entry's next renewal to no
later than the observation, and it wakes the heartbeat loop. Re-enabling
eligibility alone would leave the deadline the stale tick pushed past the
durable expiry, so a healthy Execution would still lose authority to the
Scheduler's own schedule. The observer performs this through
`SupervisionFreshnessSink`; the renewal itself stays with the heartbeat loop.

## Production API trust boundary

M5.8 freezes which surface is supported, because a correct runtime is not
enough if a consumer can rebuild a second one from adjacent public types.

```text
Supported production API
    agentype-runtime
        SchedulerDaemonBuilder
        RunningSchedulerDaemon
        SchedulerControl
        configuration / adapter import surfaces

Internal implementation
    agentype-storage-sqlite   (publish = false)
        Kernel
        claim / execution commitment
        recovery and renewal primitives
```

`agentype-storage-sqlite` is an internal implementation crate. Direct `Kernel`
use is not a supported Agentype production API and does not constitute a
Scheduler runtime composition plane. `SchedulerDaemon` is the sole supported
production composition root. The mechanical Kernel methods are additionally
compiled out unless the `runtime-internal` feature is requested, and only
`agentype-runtime` requests it.

The claim this supports is exactly:

> SchedulerDaemon is the sole supported production composition root.
> Runtime-mechanical Kernel and supervision APIs belong to non-published
> internal implementation surfaces and are not exposed through the supported
> production API.

This is a package trust boundary, not a capability sandbox. A Cargo feature is
not an unforgeable capability: a repository consumer that deliberately depends
on the non-published internal crate, and requests its `runtime-internal`
feature, can still call the mechanical Kernel surface. Making that impossible
needs an unforgeable runtime-authority capability, which is deliberately
**not** part of M5.8.

`SupervisionService` is likewise not part of the supported surface: it is
crate-private, so its constructor, `admit`, `enable_freshness_gate`, and the
`renew_one` / `renew_due` / `renew_due_now` renewal surface are not callable
from outside the Runtime. A consumer cannot assemble a supervisor that
bypasses `PhysicalObserver → freshness → SupervisionRunner`. The same holds
for the rest of the daemon's mechanical composition — `ControlLoopService`,
`ControlLoopRunner`, `PhysicalObserverService`, `PhysicalObserverRunner`,
`DispatchGate`, `ReadyPermit`, `SupervisionRegistry`, `SupervisionAdmitSink`,
`RecoveredRuntime`, and the recovery entry points — which are `pub(crate)`, or
reachable only under the `test-support` gate.

### Boundary evidence

The freeze is mechanically checked, not asserted. `crates/agentype-runtime`
documents the supported entry points, and `tests/public-api` is an
external-consumer fixture that depends on `agentype-runtime` (default
features) and holds one rustdoc probe per boundary item:

```text
no Kernel handle nameable from the runtime surface
no Dispatcher construction
no SupervisionService construction
no periodic renewal
no raw recovery
no Kernel from RunningSchedulerDaemon
no worker ACK/NACK through SchedulerControl
no ReadyPermit minting
no direct runtime worker construction
```

Each probe is a `compile_fail` doctest, so widening the production API turns
the fixture red. One `no_run` doctest holds the positive half — the supported
`SchedulerDaemonBuilder → RunningSchedulerDaemon → SchedulerControl`
composition must keep compiling. CI runs the fixture as its own
`cargo test -p agentype-public-api-boundary` invocation, because the workspace
`--all-features` run switches `test-support` on and would defeat the probes.

## READY publication

READY has one linearization point. Workers do not run before it, and
validation and publication cannot be separated.

```text
recovery + activation sweep
        ↓
start observer, control, watchdog  (workers PAUSED behind ReadyRelease)
        ↓
supervision readiness barrier
        │   no observation or heartbeat may change renewal eligibility or
        │   the renewal schedule while it is held
        ├── validate: every current authority RUNNING, owned here, fresh,
        │             renewal eligible
        ├── DispatchGate Closed → Ready      ← the linearization point
        └── release the workers
        ↓
observer and control enter steady state
```

Two separations are load-bearing. The readiness validation and the gate flip
happen inside one barrier, so the invariant is decided against a state that
nothing else can be mutating. The workers start paused, so a steady-state
observation — which may stop renewal eligibility — cannot land between the
validation and the publication.

Runner health is read before the barrier, not inside it: reading a runner's
state lock while holding the supervision registry lock would invert the
state → registry order that `refresh_positive` establishes. It is not needed
inside either, because every runner fatal publishes to the dispatch gate
synchronously, which makes `try_commit_ready` the authoritative interlock.

A worker that degrades immediately *after* publication is ordinary runtime
change; the invariant is claimed at the instant of the flip, not forever.

## Roles

| Layer | Owns |
| --- | --- |
| Process lock | OS exclusive ownership of one store |
| SupervisionRunner | Lease renewal, gated by process-local freshness |
| PhysicalObserver | Exact RUNNING / physical end / identity lost. Never renews. |
| ControlLoop | expire / retry promote / pool / bounded dispatch |
| SchedulerControl | host control and diagnostics. No Worker ACK, no mechanics. |
| Notifier | durable Root wakeup delivery |
| ExecutionAdapter | physical environment only. Collect is not Task Result. |

## Shutdown

`request_shutdown` / `join`: stop dispatch, join control, observer,
supervision, notifier, then release the process lock.

Shutdown does not ACK Tasks, invent quiescence, or kill external agents.
